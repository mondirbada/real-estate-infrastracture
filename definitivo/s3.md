# S3 — bucket del sito e bucket dei file

S3 è l'object storage di AWS: oggetti (file più metadati) in *bucket*, accessibili via API HTTP. Il progetto ha due
bucket **privati**: uno con la SPA, letto dalla distribuzione CloudFront del sito; uno con le foto e i video degli
annunci, scritti dal browser con un presigned POST e letti dalla distribuzione CloudFront dei file.

## Collegamenti

| Direzione | Bucket | Con chi | Come | Autorizzato da |
| --- | --- | --- | --- | --- |
| CloudFront → S3 | sito | [cloudfront.md](cloudfront.md) | OAC, `s3:GetObject` | bucket policy del sito |
| Deploy → S3 | sito | identità di deploy | upload dei file della SPA | permessi dell'identità di deploy ([iam.md](iam.md#identità-di-deploy-e-iampassrole)) |
| Browser → S3 | file | SPA | `POST` con il presigned POST | firma della [Presigned Lambda](lambda-presigned.md) (`s3:PutObject`) + CORS del bucket |
| S3 → Files Lambda | file | [lambda-files.md](lambda-files.md) | notifica `ObjectCreated` su `uploads/` | resource policy della Files Lambda |
| Files Lambda → S3 | file | [lambda-files.md](lambda-files.md) | `DeleteObject` via gateway endpoint S3 ([vpc-endpoints.md](vpc-endpoints.md)) | ruolo della Files Lambda |
| CloudFront → S3 | file | [cloudfront.md](cloudfront.md) | OAC, `s3:GetObject` su `uploads/*` | bucket policy dei file |

## Cos'è

- Un **bucket** ha un nome unico in tutto il mondo ed è legato a una regione; la **chiave** di un oggetto è una stringa
  (`uploads/<propertyId>/<uuid>.jpg`), non una vera cartella.
- Durabilità di 11 nove; i dati sono replicati su più AZ nelle classi standard.
- Funzioni note ma non usate: versioning, lifecycle rules (spostare o cancellare oggetti dopo N giorni, anche gli
  upload incompleti), classi di storage diverse (IA, Glacier).
- Gli eventi S3 (`ObjectCreated` e altri) possono invocare Lambda, SQS o EventBridge: per esempio per generare
  miniature. Noi li usiamo per registrare gli upload.

## Configurazione

| Bucket | Contenuto | Letto da | Scritto da |
| --- | --- | --- | --- |
| `real-estate-prod-website-<SUFFIX>` | La SPA (HTML, JS, CSS) | distribuzione CloudFront del sito | chi fa il deploy |
| `real-estate-prod-files-<SUFFIX>` | File degli annunci, sotto `uploads/` | distribuzione CloudFront dei file | il browser, con il presigned POST |

`<SUFFIX>` rende unici i nomi dei bucket. Su entrambi:

- **Block Public Access** attivo e ACL disattivate (*Object Ownership: bucket owner enforced*). I file "pubblici" lo sono
  solo tramite CloudFront; il presigned POST funziona lo stesso, perché è firmato da un ruolo IAM e non è un accesso
  pubblico.
- Nessuno *static website hosting*: il sito è servito da CloudFront.
- Cifratura a riposo **SSE-S3**, gratuita; l'alternativa SSE-KMS darebbe controllo sulla chiave ([kms.md](kms.md)).
- Bucket policy con OAC e Deny delle richieste senza TLS.

### Upload con presigned POST

Il browser scrive nel bucket dei file **senza credenziali AWS proprie**: usa il presigned POST firmato dalla Presigned
Lambda, che ha `s3:PutObject` solo su `uploads/*`. Il file va direttamente dal browser a S3: la Lambda non fa da tramite
per i dati (API Gateway accetta al massimo 10 MB e una Lambda sincrona 6 MB). Il POST e non il PUT perché solo il POST
permette le *conditions* `content-length-range` e `Content-Type`. Dettagli e condizioni in
[lambda-presigned.md](lambda-presigned.md).

Non serve nulla nella bucket policy: nello stesso account basta il permesso del ruolo che firma.

### CORS del bucket dei file

Il sito (dominio CloudFront) e il bucket hanno origini diverse: senza una regola CORS il browser bloccherebbe l'upload.
La regola (`PutBucketCors`) permette il `POST` dall'origine del sito.

File: [`config/s3-files-cors.json`](config/s3-files-cors.json)

```json
{
  "CORSRules": [
    {
      "ID": "AllowPresignedPostFromSite",
      "AllowedOrigins": [
        "https://<SITE_DOMAIN>"
      ],
      "AllowedMethods": [
        "POST"
      ],
      "AllowedHeaders": [
        "*"
      ],
      "MaxAgeSeconds": 3000
    }
  ]
}
```

### Notifica `ObjectCreated` verso la Files Lambda

Quando un upload termina, S3 invoca la Files Lambda, che registra il file nel database. Così il database viene
aggiornato solo dagli upload riusciti, senza fidarsi di una conferma del client. Configurazione
(`PutBucketNotificationConfiguration`), solo prefisso `uploads/`:

File: [`config/s3-files-notification.json`](config/s3-files-notification.json)

```json
{
  "LambdaFunctionConfigurations": [
    {
      "Id": "RegisterCompletedUploads",
      "LambdaFunctionArn": "arn:aws:lambda:eu-south-1:<ACCOUNT_ID>:function:real-estate-prod-files",
      "Events": [
        "s3:ObjectCreated:*"
      ],
      "Filter": {
        "Key": {
          "FilterRules": [
            {
              "Name": "prefix",
              "Value": "uploads/"
            }
          ]
        }
      }
    }
  ]
}
```

Va applicata **dopo** il permesso [`lambda-files-allow-s3.json`](iam/resource-policies/lambda-files-allow-s3.json)
sulla funzione, altrimenti S3 la rifiuta (spiegato in [lambda-files.md](lambda-files.md#iam)). L'invocazione la fa il
servizio Lambda, non passa dalla rete della VPC: per questo non serve un endpoint.

## Bucket policy

CloudFront non ha un ruolo: firma le richieste con OAC e la bucket policy ammette solo la distribuzione giusta. Ogni
policy ha due statement:

1. `Allow` per il principal `cloudfront.amazonaws.com`, azione `s3:GetObject`, con la condizione `AWS:SourceArn` = ARN
   della distribuzione. Senza la condizione una distribuzione di un altro account potrebbe leggere il bucket.
2. `Deny` per tutti (`"Principal": "*"`) delle richieste senza TLS (`aws:SecureTransport = false`). Un Deny esplicito
   vince su qualunque Allow.

Bucket del sito:

File: [`iam/resource-policies/s3-website-bucket-policy.json`](iam/resource-policies/s3-website-bucket-policy.json)

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowCloudFrontSiteDistributionReadOnly",
      "Effect": "Allow",
      "Principal": {
        "Service": "cloudfront.amazonaws.com"
      },
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::real-estate-prod-website-<SUFFIX>/*",
      "Condition": {
        "StringEquals": {
          "AWS:SourceArn": "arn:aws:cloudfront::<ACCOUNT_ID>:distribution/<DIST_SITE_ID>"
        }
      }
    },
    {
      "Sid": "DenyRequestsWithoutTls",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:*",
      "Resource": [
        "arn:aws:s3:::real-estate-prod-website-<SUFFIX>",
        "arn:aws:s3:::real-estate-prod-website-<SUFFIX>/*"
      ],
      "Condition": {
        "Bool": {
          "aws:SecureTransport": "false"
        }
      }
    }
  ]
}
```

Bucket dei file, con lettura limitata a `uploads/*`:

File: [`iam/resource-policies/s3-files-bucket-policy.json`](iam/resource-policies/s3-files-bucket-policy.json)

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowCloudFrontFilesDistributionReadOnly",
      "Effect": "Allow",
      "Principal": {
        "Service": "cloudfront.amazonaws.com"
      },
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::real-estate-prod-files-<SUFFIX>/uploads/*",
      "Condition": {
        "StringEquals": {
          "AWS:SourceArn": "arn:aws:cloudfront::<ACCOUNT_ID>:distribution/<DIST_FILES_ID>"
        }
      }
    },
    {
      "Sid": "DenyRequestsWithoutTls",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:*",
      "Resource": [
        "arn:aws:s3:::real-estate-prod-files-<SUFFIX>",
        "arn:aws:s3:::real-estate-prod-files-<SUFFIX>/*"
      ],
      "Condition": {
        "Bool": {
          "aws:SecureTransport": "false"
        }
      }
    }
  ]
}
```

CloudFront non ha `s3:ListBucket`: per un oggetto che non esiste S3 risponde 403 invece di 404
([cloudfront.md](cloudfront.md#configurazione)).

## IAM

- Bucket policy: sopra.
- Chi scrive: la Presigned Lambda firma con `s3:PutObject` su `uploads/*` ([lambda-presigned.md](lambda-presigned.md#iam)).
- Chi cancella: la Files Lambda con `s3:DeleteObject` su `uploads/*` ([lambda-files.md](lambda-files.md#iam)). La Files
  non ha `s3:GetObject`: chiave e dimensione arrivano nell'evento della notifica.
- Chi può invocare la Files Lambda: [`lambda-files-allow-s3.json`](iam/resource-policies/lambda-files-allow-s3.json).

## Sicurezza e rete

- S3 è un servizio regionale fuori dalla VPC: niente security group.
- Dalla VPC si raggiunge con il **gateway endpoint S3**, gratuito ([vpc-endpoints.md](vpc-endpoints.md)).
- La chiave dell'oggetto la decide la Presigned Lambda (`uploads/<propertyId>/<uuid>.<ext>`), non il client; il POST
  scade in 5 minuti; tipo e dimensione sono limitati dalle conditions.
- Scansione antivirus dei file caricati: sviluppo futuro.

## Costi

Storage, richieste e trasferimento: con i volumi del progetto pochi centesimi. Il gateway endpoint è gratuito.

## Punti aperti

- **File di un immobile cancellato:** la riga sparisce dal database ma gli oggetti restano su S3. Per il progetto è
  accettato; sviluppo futuro: un evento che li fa cancellare alla Files Lambda
  ([decisioni-e-punti-aperti.md](decisioni-e-punti-aperti.md#punti-aperti)).

## All'orale

> **Perché il bucket del sito è privato?**
> Lo legge solo CloudFront con OAC: niente accesso diretto, HTTPS e cache garantiti, Block Public Access attivo.
>
> **Perché il presigned POST invece di far passare il file dalla Lambda?**
> API Gateway accetta al massimo 10 MB e una Lambda sincrona 6 MB; con il presigned il file va dal browser a S3 senza
> passare dal backend. È come un endpoint Spring che invece di ricevere il `MultipartFile` restituisce al client un
> permesso firmato per caricarlo da solo.
>
> **Che permessi ha un presigned POST?**
> Al massimo quelli di chi lo firma: `s3:PutObject` solo su `uploads/*`. Tipo e dimensione li limitano le conditions,
> non IAM.
>
> **Come sa il database che un upload è andato a buon fine?**
> La notifica `ObjectCreated` sul prefisso `uploads/` invoca la Files Lambda, che registra il file. Non ci fidiamo di
> una conferma del client.
>
> **Perché serve il CORS sul bucket?**
> Perché il browser fa un `POST` dal dominio del sito al dominio del bucket: senza la regola lo bloccherebbe.
>
> **I file caricati sono pubblici?**
> Sì, tramite la distribuzione CloudFront dei file: chi ha il link li vede, come le foto di un annuncio. Il bucket
> resta privato.
